# gdb

### GDB 调试速查笔记

#### 1. 编译准备

调试前必须加上 `-g` 参数生成调试信息，建议加上 `-O0` 关闭优化。

```bash
gcc -g -O0 test.c -o test
```

#### 2. 启动 GDB

- **常规启动**：`gdb ./test`
- **带参数启动**：`gdb --args ./test arg1 arg2`
- **附加进程调试**：`gdb -p <进程PID>`

#### 3. 核心命令速查表

|分类|命令 (简写)|作用说明|
|:--|:--|:--|
|**运行控制**|`run` (r)|从头运行程序|
||`start`|运行并自动停在 main 函数第一行|
||`continue` (c)|继续执行直到下一个断点|
||`quit` (q)|退出 GDB|
|**断点管理**|`break 行号/函数` (b)|设置断点 (如 `b 10` 或 `b main`)|
||`info break` (i b)|查看当前所有断点|
||`delete 断点编号` (d)|删除指定编号的断点|
|**单步调试**|`next` (n)|单步执行（不进入函数内部）|
||`step` (s)|单步执行（会进入函数内部）|
||`finish`|执行完当前函数并跳出|
|**查看状态**|`print 变量` (p)|打印变量的当前值|
||`display 变量`|每次暂停时自动打印该变量|
||`backtrace` (bt)|查看函数调用栈（排查崩溃必用）|
||`list` (l)|查看当前附近的源代码|

#### 4. 进阶调试技巧

- **条件断点**：只在满足条件时暂停。
    - 例：`b 20 if i == 100` （当变量 i 等于 100 时在第 20 行暂停）
- **观察点 (Watchpoint)**：监控变量，一旦值被改变就暂停。
    - 例：`watch global_var`
- **动态修改变量**：在调试中强行改变变量值。
    - 例：`set var flag = 1`
- **多线程调试**：
    - `info threads`：查看所有线程
    - `thread <ID>`：切换线程
    - `thread apply all bt`：查看所有线程的调用栈（排查死锁）


## **TUI**
GDB TUI（Text User Interface）模式是 GDB 自带的一个非常实用的“文本图形界面”。它能让你在终端里像 IDE 一样，**一边看高亮的源代码，一边敲调试命令**，再也不用反复敲 `list` 命令来查看代码走到哪一行了。

结合你刚才正在调试 `ga` 程序，以下是 GDB TUI 的核心使用指南：

### 🚀 如何开启 TUI 模式

你有三种方式可以进入 TUI 模式：

1. **启动时直接进入**：`gdb -tui ga`
2. **在 GDB 内部切换**：在 `(gdb)` 提示符下输入 `tui enable`
3. **快捷键切换（最常用）**：在 GDB 中直接按下 **`Ctrl + x`，松开后再按 `a`**（即 `Ctrl+x a`），可以随时在普通模式和 TUI 模式之间来回切换。

### 🖥️ 核心窗口布局（`layout` 命令）

进入 TUI 后，你可以通过 `layout` 命令调整显示的窗口：

- **`layout src`**：只显示源码窗口（最常用，清晰直观）。
- **`layout asm`**：显示汇编代码窗口（想看底层指令时用）。
- **`layout regs`**：显示寄存器窗口（通常和源码或汇编窗口一起出现，实时查看寄存器值的变化）。
- **`layout split`**：同时显示源码和汇编窗口。

### ⌨️ 常用快捷键速查

在 TUI 模式下，键盘操作会变得更高效：

| 快捷键                   | 作用说明                         |
| :-------------------- | :--------------------------- |
| **Ctrl+x a**          | 快速开启/关闭 TUI 模式               |
| **Ctrl+L**            | **刷新屏幕**（如果界面乱码或错位，按这个准没错）   |
| **Ctrl+x o**          | 在源码窗口和命令窗口之间**切换焦点**         |
| **PageUp / PageDown** | 在源码窗口中上下翻页浏览代码               |
| **Ctrl+p / Ctrl+n**   | 翻看历史命令（因为方向键在 TUI 里通常用来滚动窗口） |

### 💡 调试小贴士

- **编译要求**：要想在 TUI 里看到源码，编译时必须加上 `-g` 参数（你之前的 `gcc -g sperf.c -o ga` 已经完美满足了这一点）。
- **界面乱了怎么办？**：在终端调试时，如果因为窗口缩放或打印日志导致界面显示错乱，按下 **`Ctrl+L`** 就能强制重绘，瞬间恢复正常。
- **退出 TUI**：按 `Ctrl+x a` 切回普通命令行，或者直接输入 `quit` 退出 GDB。

你可以现在就在你的 `(gdb)` 界面里按一下 `Ctrl+x a`，马上就能体验到带源码高亮的调试界面了！
